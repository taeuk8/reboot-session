# Reboot Session — Windows 작업 환경 복원 앱

**v0.1 프로토타입 구현됨. 실행·지원 범위는 [START_HERE.md](START_HERE.md)를 먼저 읽어주세요.**

아래는 제품 목표와 설계이며, 아직 구현하지 않은 항목도 포함합니다.

## 목표

사용자가 재시작 직전에 현재 작업 환경을 수집하고, 복원 예정 목록을 확인한 뒤 Windows를 재시작하면 다음 로그인 후 작업 환경을 다시 구성한다.

자동 주기 저장은 초기 범위에서 제외한다. 프로세스 메모리를 복제하는 방식이 아니라, 프로그램별 재개 기능과 저장된 파일·경로·배치를 이용한다.

## 사용자 흐름

1. 앱에서 **재시작 준비**를 누른다.
2. 실행 중인 지원 프로그램과 복원 가능한 상태를 수집한다.
3. 목록에서 항목을 선택하고, 복원 범위와 확인 필요 사항을 검토한다.
4. **저장하고 다시 시작**을 누른다.
5. 상태를 다시 수집한다. 중요한 변경이 있으면 갱신된 목록을 다시 확인받는다.
6. 복원 계획을 파일에 원자적으로 기록하고 다시 읽어 검증한다. 실패하면 재시작하지 않는다.
7. 해당 Windows 사용자에게 로그인 후 실행될 일회성 복원 작업을 등록한다. 등록 실패 시 재시작하지 않는다.
8. Windows의 정상 재시작을 요청한다. 앱 종료를 강제하지 않으며, 저장 확인이나 사용자 취소를 존중한다.
9. 다음 로그인 후 복원 계획에 따라 순차적으로 실행한다.
10. 성공·실패·사용자 확인 필요 결과를 표시한다. 실패한 항목만 재시도할 수 있다.

## 화면 초안

### 재시작 준비

```text
재시작 후 복원할 작업

[✓] WezTerm                 [세부 항목 보기]
    프로젝트 A · AI 대화 세션
    프로젝트 B · AI 대화 세션
    개발 서버 · 사용자가 등록한 실행 명령
[✓] Chrome                  프로필별 창과 탭
[✓] Excel                   열려 있는 통합 문서
[✓] 탐색기                  열려 있는 폴더

확인 필요
· 저장하지 않은 문서는 저장 후 다시 확인해주세요.
· 지원하지 않는 항목은 복원 범위가 제한됩니다.

[목록 새로고침] [취소] [저장하고 다시 시작]
```

로그인 상태의 유지 여부를 모든 앱에서 사전 판별할 수 있다고 표시하지 않는다. 각 항목에는 실제 확인한 정보만 보여준다.

### 복원 결과

항목별로 대기 / 복원 중 / 완료 / 실패 / 사용자 확인 필요 상태를 표시한다. 재시도와 결과 닫기를 제공한다. 재시도 시 이미 열린 항목을 중복 생성하지 않도록 확인한다.

## 복원 대상과 한계

| 대상 | 목표 | 주의 사항 |
| --- | --- | --- |
| WezTerm | 창·탭·분할 구성, 셸, 작업 경로 | Windows에서 얻을 수 있는 정보와 레이아웃 재현 API를 먼저 검증 |
| Codex·OpenCode | 패널별 프로젝트와 특정 대화 세션 재개 | 설치 버전별 세션 식별·재개 방식 검증 필요. 마지막 세션 하나로 일괄 복원하지 않음 |
| 개발 서버 | 사용자가 복원용으로 지정한 명령 실행 | 터미널 명령 기록을 임의로 재실행하지 않음 |
| Chrome | 프로필별 창·탭·활성 탭 | 확장 프로그램 등 연동 방식 검증 필요. URL만으로 폼·스크롤·로그인을 보장할 수 없음 |
| Excel | 저장된 파일 다시 열기, 가능하면 시트·선택 위치 | 미저장 변경과 새 통합 문서는 저장을 안내. COM 연동 검증 필요 |
| 탐색기 | 폴더 다시 열기 | 탭 구성과 선택 항목 지원 여부 별도 검증 |
| 창 배치 | 모니터별 위치·크기·최대화 상태 | 모니터 구성이 바뀌면 현재 화면 안으로 재배치 |
| 기타 앱 | 지원되는 실행 파일과 문서 다시 열기 | 앱별 내부 작업 상태는 전용 연동이 필요 |

동일 Windows 사용자와 기존 앱 프로필을 사용한다. 비밀번호·쿠키·인증 토큰을 스냅샷에 복사하지 않는다. 인증 만료 시 사용자가 다시 로그인한다. 로컬 작업 경로와 대화 식별자 등은 사용자 전용 로컬 데이터로 보관한다.

## 첫 버전 범위

첫 구현은 Windows 11 단일 사용자 환경을 기준으로 한다. 지원 OS 범위는 실제 사용자 PC 확인 후 조정한다.

1. **수집·복원 검증 도구**: 재부팅 없이 상태를 저장하고 수동 복원한다. WezTerm 패널 하나와 AI 세션 하나부터 검증한다.
2. **핵심 앱**: 선택 목록, 상태 파일 검증, 로그인 후 복원, 정상 재시작, 항목별 결과·재시도를 연결한다.
3. **업무 앱 연동**: Chrome, Excel, 탐색기와 창 배치를 순차적으로 추가한다. 연동이 없는 앱을 완전 복원으로 표시하지 않는다.

개발 환경에서 실제 Windows 재시작은 기본 검증으로 실행하지 않는다. 먼저 모의 재시작과 수동 복원을 검증하고, Windows에서 사용자가 준비한 작업으로 실제 재시작 검증을 진행한다.

## 구현 방향 — 제안

Windows 전용 .NET 데스크톱 앱과 프로그램별 어댑터로 구성한다. UI 프레임워크와 런타임 버전은 착수 시 지원 환경을 확인한 뒤 선택한다.

- 수집기: 실행 중인 프로그램과 지원 앱의 상태 읽기
- 어댑터: 앱별 상태 수집, 복원 계획 생성, 복원 및 결과 확인
- 계획 저장소: 버전이 있는 JSON, 임시 파일 작성 후 교체, 재읽기 검증
- 복원 실행기: 의존 순서, 제한 시간, 중복 실행 방지, 항목별 재시도
- 재시작 담당: 로그인 후 복원 등록과 정상 재시작 요청

복원 계획에는 계획 ID, 형식 버전, 생성 시각, 사용자 식별, 항목 ID, 앱 종류, 프로젝트·문서 경로, 프로필·대화 식별자, 창 배치, 의존 항목을 저장한다. 실행 결과는 계획과 별도로 기록한다.

진행 상태는 `준비 → 수집 → 검토 → 저장 → 로그인 후 실행 등록 → 재시작 요청 → 복원 → 완료/부분 실패`로 관리한다. 재시작이 취소되면 등록한 작업을 정리한다. 복원 작업이 오래 지난 상태거나 이미 완료된 계획이면 자동 재실행하지 않는다. 복원 중 앱이나 PC가 종료되어도 무한 재실행하지 않도록 실행 횟수와 진행 기록을 둔다.

## 구현 전 확인할 정보

- Windows 버전과 WezTerm 버전
- Codex·OpenCode가 Windows 네이티브 셸에서 실행되는지, WSL인지, 원격 SSH인지
- Chrome 프로필 수와 확장 프로그램 설치 가능 여부
- 데스크톱 Excel 설치 여부와 주로 쓰는 로컬/클라우드 문서

이 정보가 아직 없어도 UI와 계획 저장·복원 실행 구조는 개발할 수 있다. 세션 연결 구현은 실제 실행 환경을 확인한 뒤 확정한다.

## 완료 기준

- 재부팅 없이 저장·복원 결과를 먼저 확인할 수 있다.
- 저장 실패나 로그인 후 실행 등록 실패 시 재시작하지 않는다.
- 지원 항목과 복원할 수 없는 상태가 검토 화면에 구분되어 표시된다.
- 서로 다른 프로젝트의 AI 세션 두 개를 각각 올바른 패널에 재개한다.
- 사용자가 선택하지 않은 항목과 등록하지 않은 명령은 실행하지 않는다.
- 정상 재시작이 취소되거나 일부 복원이 실패해도 계획과 결과가 남는다.
- 복원 재시도와 앱 재실행이 이미 복원된 항목을 중복 생성하지 않는다.
- 최종 Windows 검증에서 로그인 후 선택한 지원 항목이 복원되고 결과가 표시된다.
